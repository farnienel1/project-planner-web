# Project Planner web

Business rules that the iOS app must also follow live in `lib/canonical/`. Read `docs/CANONICAL_ARCHITECTURE.md` before changing bookings, warnings, invoicing, labour, organisation context, or dates.

## Rules

1. Canonical business logic. Search `lib/canonical` before adding or changing a business rule. Do not implement that rule again in a page, store, or hook.
2. Organisation context. Organisation-scoped reads and writes use `adoptCurrentOrganization` / `organizationContextStillCurrent`. Do not infer the open company from a stale user field, a cache entry, or another organisation's listener.
3. Architectural changes. A change to business logic, data access, organisation handling, or cross-platform behaviour updates `lib/canonical` and `docs/CANONICAL_ARCHITECTURE.md` in the same change.
4. New business logic. A rule that both web and iOS must share is added under `lib/canonical/` and the canonical bundle. UI and navigation stay in the app. Qualification, unverified, and unbooked warning rows are `lib/canonical/warningRows.ts`. An anonymised deleted profile is never a current warning, Daily Overview unbooked row, or new weekly-report warning — `listedCurrentLabourPeople` / `isAnonymisedDeletedProfile`. Historic bookings keep the stored name. Ordering already-computed warning rows by coverage day is `lib/canonical/warningSort.ts` (`sortWarningsByDate`); the Oldest/Newest preference stays in each app (web localStorage, iOS UserDefaults) and is not an organisation setting. Assigned qualification write shape, certificate URL merge, and the certificate storage path are `lib/canonical/operativeQualifications.ts`. Annual leave against bookings is `lib/canonical/leaveCoverage.ts`. Allowance vs year-count, the leave year, and a one-year remaining override are `lib/canonical/annualLeaveBalance.ts`. Material catalogue search is `lib/canonical/materialSearch.ts`. The default required-delivery instant on a material order (tomorrow 08:00, or Monday 08:00 when Send is opened on Saturday or Sunday) and that a quote never includes a day or time are `lib/canonical/materialDelivery.ts`. Timesheet submit deadline and reminder notify-at (close of play the day before payday; 08:00 three days before), generated notice copy, and which occurrence is due are `lib/canonical/timesheetSubmission.ts`. Timesheet period identity, Awaiting / Signed off / Exported, sign-off and export write fields, and selectable historical payment-run periods are `lib/canonical/timesheetPeriod.ts` (`timesheetListBucket`, `selectableTimesheetPaymentRunPeriods`, `timesheetSignOffWriteFields`). Do not invent a second status enum or rematch a stored 1–7 window onto a live 1–15 setting. Organisation subscription access is `lib/canonical/billingAccess.ts` (`hasAccess`): missing billing, none, pending, trialing, and active stay open; past_due stays open within 7 days of `lastPaymentFailedAt`; canceled, unpaid, paused, incomplete, and expired past_due stay closed; cancel-at-period-end stays open while status is still active. Do not invent a second billing-status enum. Session company choice is `chooseSessionOrganization` in `lib/canonical/engine.ts` (explicit switch, then this device’s remembered key, then `users/{uid}.organizationId`). Web key `pp.webActiveOrg:{userId}`; iOS key `cached_organizationId`. Same-user sign-out must not clear that key. A slow membership read is `unknown` and must not drop the remembered company. The switcher list is `sessionMembershipIds` — a members/creator query must not hide a known company, including when that query finished but omitted it. Company name is `parseOrganizationName` / `organizationNameWriteFields` — a blank must not persist over a saved `organizations/{orgId}.name`. The standard day and its AM/PM halves are `halfDayWindows` in `lib/canonical/engine.ts`; never compute a midpoint elsewhere. Who sees every job, every warning, and every variation, who may add or edit a work catalogue, and which managers receive a job notification are `lib/canonical/staffAccess.ts`. Organisation settings defaults, payment-run field names, warningDetection, and the organisation material cut-off clock (`parseMaterialCutOff`, `resolveMaterialCutOffClock`) are `lib/canonical/organizationSettings.ts`. Do not treat `users/{uid}.notificationPreferences.materialCutOffHour` as the clock. A missing hour defaults to 16; a saved 15:30 stays 15:30. The `users/{uid}` document, employment-type day rule, and Edit User permission copy are `lib/canonical/userProfile.ts`. Roster Active / Inactive / Pending is `lib/canonical/userRosterSegment.ts` (`userRosterSegment`, `matchesRosterSegment`, `listedRosterUsers`). An anonymised deleted profile (empty email and “Deleted user”) is Inactive even when `passwordSet` and `isActive` are true. Do not drop that empty-email tombstone from the org `users` query; it is not a live pending leftover. Re-invite of the same email is a new row. Current warnings and scheduling pickers use `listedCurrentLabourPeople` — do not invent a second Deleted-user check in a screen. A leftover pending row that still has a real name, email, or phone after `organizations/{orgId}/userEmails/{email}` is gone is not Pending. Do not invent a second Active/Inactive/Pending calculator in a screen. User-level My notifications toggles, inbox destination kinds, device-push allow-list, unread badge, and which inbox rows belong to the signed-in user are `lib/canonical/notificationPreferences.ts` (`parseUserNotificationPreferences`, `notificationPreferenceAllowsDelivery`, `notificationDestination`, `devicePushNotificationTypes`, `notificationDeliversDevicePush`, `unreadNotificationBadgeCount`, `inboxNotificationVisibleToUser`). Who is written onto a job/booking row stays `receivesJobNotification`. The centre reads `userId == signed-in user`, not the whole company collection. Both apps write the same `users/{uid}.notificationPreferences` keys with dotted updates. Do not invent a second toggle list, deep-link map, or unread counter in a screen. Who is on a job/booking fan-out stays `receivesJobNotification`. Web does not send browser or OS notifications.
5. Discrepancies. If web and iOS disagree, find the first divergence (database, query, organisation context, business rule, date rule, cache, then UI). Do not patch the screen to copy the other platform's number.
6. Regression tests. A cross-platform discrepancy gets a test in `lib/canonical/canonical.test.ts` that locks the shared result.

A commit that touches `lib/canonical` packs the rulebook through `.githooks/pre-commit` and stages `lib/canonical/dist/canonical-business.js`. When `../project-planner-ios` is checked out, that commit is refused until `Project Planner/Canonical/canonical-business.js` is committed there. `npm test` packs and then runs `npm run check:canonical`. An agent window with only this repo must not hand-edit the iOS script. An agent window with only the iOS repo calls `CanonicalBusinessEngine` and does not add a second calculator for a rule this module already owns.
