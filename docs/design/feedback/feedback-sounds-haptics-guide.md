# Project Planner: sound and haptic feedback guide (web + iOS)

**Version 1.2, 24 Nov 2026.** This is the single shared spec for feedback sounds (web and iOS) and haptics (iOS only).

Put an identical copy in both repos at `docs/design/feedback/feedback-sounds-haptics-guide.md`. Web is the source; iOS copies it, the same way it mirrors the rulebook.

**This is not a business rule.** It changes no data, calculation, permission, sync or flow. It adds a short sound, and on iPhone a tap, **after** an action has already succeeded or been refused. It does not go in `docs/RULEBOOK.md` and needs no rulebook version bump. It belongs with "Platform-specific (not synced)" (rulebook §15).

---

## 1. Principles

1. **Feedback confirms an outcome, never a tap.**
   - Play a sound or haptic only when the save, request, approval or resolve has **actually succeeded**, or has been **refused**.
   - Never play it when the button is pressed. Never play "success" before the result is known.
2. **Only for things *this person* did *on this device*.**
   - No sound for live updates from other people or devices.
   - No sound for listeners refreshing, app launch, background sync, push notifications arriving, or screens loading.
3. **One action, one sound.** A bulk action (book 12 people, approve 5 requests) plays **one** sound at the end. Throttle: at most one feedback sound every 400 ms.
4. **Quiet and short.** Every sound is under 650 ms (the one exception is the sign-in chord, §2.1, about 2.6 s), peaks at −6 dBFS in the file, and plays at a low volume (web gain 0.35). Nothing loops, no music and no voice.
5. **Respect the person and the device.**
   - **iOS:** sounds use the `.ambient` audio session, so the **silent switch mutes them** and they never stop someone's music or podcast. Haptics follow the system "System Haptics" setting automatically.
   - **Web:** sounds play only after a user gesture, which our actions always are. They never interrupt other tabs.
   - **Both:** a **Sounds** on/off setting. iOS also gets a **Haptics** on/off setting. Both are stored **on this device only** (`UserDefaults` / `localStorage`), with no Firestore, rules or sync change.
6. **Never the only signal.** The existing toast, banner, checkmark or error text stays exactly as it is. Sound and haptics are extras. Someone who is deaf, uses VoiceOver, or has sound off loses nothing.
7. **Errors are gentle.** "Refused" is a soft low tone, not an alarm. No sound for validation messages shown while typing; only when a submit is refused.

## 2. The sound palette (7 sounds, shared by both platforms)

| Sound | File | Feel | Length |
|---|---|---|---|
| `success` | `pp-success` | Soft rising two-note chime (E5 → B5) | 400 ms |
| `sent` | `pp-sent` | Light upward "pop", for something sent off for someone else to decide | 160 ms |
| `approved` | `pp-approved` | Bright four-note rising arpeggio (C–E–G–C), for the bigger moments | 620 ms |
| `resolved` | `pp-resolved` | Gentle falling two-note "settle" (G5 → D5), for a problem dealt with | 460 ms |
| `removed` | `pp-removed` | Single soft low note, neutral and not negative | 240 ms |
| `error` | `pp-error` | Two soft low tones, for refused or failed | 280 ms |
| `queued` | `pp-queued` | Tiny tick, for saved on this device and syncing when back online (iOS offline) | 90 ms |

**Generating the files.** They are generated by `scripts/feedback-sounds/make_feedback_sounds.py` (in §6), which is deterministic and licence-free, with no third-party samples.
- **Web** commits:
  - the `.wav` masters in `docs/design/feedback/sounds/`;
  - web copies in `public/sounds/` as `.mp3` (96 kbps mono) and `.webm` (Opus);
  - a `preview.html` for the owner to listen to all seven.
- **iOS** copies the masters from the web repo and converts them to `.caf` (`afconvert -f caff -d LEI16`) in the app bundle.
- If the owner wants a different feel, change the script, never hand-edited audio, and regenerate for both.

### 2.1 The sign-in chord (`welcome`, made in code)

Owner 24 Nov: "a nice slow harmony when you first log in — unique, generated, mind copyright". It is **not a file**: each app builds it at play time with its audio engine (web: Web Audio API oscillators; iOS: `AVAudioEngine` with `AVAudioSourceNode`, or render the same numbers to a buffer once). No samples and no melody from anywhere else: it is a plain chord, which is not protected.

| Parameter | Value |
|---|---|
| Chord | D major 9: D3, A3, F♯4, C♯5, E5 |
| Frequencies (Hz) | 146.83, 220.00, 369.99, 554.37, 659.25 |
| Waveform | sine, plus a second sine one octave up at 0.12 of the voice |
| Voice levels (before ÷ 5) | 0.55, 0.70, 0.85, 0.80, 0.65 — each voice peaks at level ÷ 5 |
| Entry | one voice every 0.16 s, lowest first |
| Attack | each voice rises linearly from silence (0.0001) to its level over 0.55 s |
| Release | each voice falls exponentially to 0.0001 at 2.6 s after the first voice entered; oscillators stop 0.05 s later |
| Master | web gain 0.35 × 0.75 (iOS: the same relative level under the `.ambient` session) |
| Length | 2.6 s |

When: once, after a successful sign-in made on this device — the password form (no code step), a passkey, or the emailed code — never on a reload or when the app reopens an existing session. Web marks it in this tab's `sessionStorage` (`pp.feedback.welcomePending`, dropped after 60 s) and the app shell plays it once and clears the mark. It follows the **Sounds** setting. Audio is primed inside the sign-in tap; if the browser still will not let audio start (for example Safari after the full page load that follows the code), nothing plays and nothing is queued. No haptic.

Web source: `lib/feedbackSounds/feedback.ts` (`WELCOME_CHORD`, `scheduleWelcomeChord`).

## 3. Haptics (iOS)

Use the existing `HSHaptic` helper (`Views/HSTheme.swift`) and extend it. Don't add a second helper.

| Haptic | API | Pairs with |
|---|---|---|
| `success` | `UINotificationFeedbackGenerator .success` | `success`, `approved`, `resolved` |
| `sent` | `UIImpactFeedbackGenerator(.light)` | `sent`, `queued` |
| `removed` | `UIImpactFeedbackGenerator(.rigid, intensity 0.6)` | `removed` |
| `error` | `UINotificationFeedbackGenerator .error` | `error` |
| `warn` | `UINotificationFeedbackGenerator .warning` | No sound. A warning appears that needs attention (e.g. a clash or unpaid-break warning shown on save) |
| `tap` / `select` | existing | No sound. Keep the current uses; don't add more |

Call `prepare()` on the generator when the confirming sheet or button appears, so the haptic lands in time with the sound.

## 4. Event catalogue: which action plays what

Each platform calls **one** function with a named event, for example `Feedback.play(.bookingSaved)` (iOS) and `feedback('bookingSaved')` (web). The event decides the sound and haptic. Screens never pick sounds themselves.

| Event | When it fires (after the existing success / refusal) | Sound | iOS haptic |
|---|---|---|---|
| `bookingSaved` | A new booking or custom booking is saved (single or bulk, one sound) | success | success |
| `bookingEdited` | An existing booking edit is saved | success | success |
| `bookingRequested` | An operative's booking request is sent for approval | sent | sent |
| `bookingApproved` | A manager approves a booking or booking request | approved | success |
| `bookingDeclined` | A manager declines a booking or request | removed | removed |
| `bookingDeleted` | A booking is deleted or cancelled | removed | removed |
| `leaveRequested` | An annual leave request is submitted | sent | sent |
| `leaveBooked` | Leave is booked directly (an admin or manager books it for someone) | success | success |
| `leaveApproved` | A leave request is approved | approved | success |
| `leaveDeclined` | A leave request is declined | removed | removed |
| `warningResolved` | A warning is dealt with: approved, dismissed, or a clash approved | resolved | success |
| `allWarningsClear` | The last open warning in the current list is resolved (replaces `warningResolved` for that action) | approved | success |
| `timesheetSigned` | A timesheet is signed | approved | success |
| `timesheetSaved` | A timesheet draft, overtime report, expense or price-work line is saved | success | success |
| `userInvited` | A new user is added or an invite is sent | sent | sent |
| `savedOffline` | iOS only: the action was saved to the offline queue (instead of the success event) | queued | sent |
| `leaveEdited` | An existing leave booking is changed, or a cancellation request is sent (owner decision 5, 16 Nov) | success | success |
| `leaveRemoved` | Someone's leave is removed by a manager or admin (owner decision 5, 16 Nov) | removed | removed |
| `overtimeSent` | A PAYE person's overtime is sent with "Send for approval" (owner decision 2, 16 Nov; reuses the `bookingRequested` sound) | sent | sent |
| `overtimeReturned` | A line manager or admin presses "Return overtime" (owner decision 2; reuses the `bookingApproved` sound) | approved | success |
| `claimsApproved` | Price work or expense review: Approve saved with at least one item approved (owner decision 2) | approved | success |
| `claimsDeclined` | Price work or expense review: Approve saved with every decided item rejected (owner decision 2) | removed | removed |
| `actionRefused` | The server or rules refused a save, request or approval, or it failed | error | error |
| `warningShown` | A blocking warning is shown on save (e.g. unpaid break, clash) | none | warn |
| `signedIn` | The person signs in on this device: password with no code step, a passkey, or the emailed code (owner 24 Nov; once, never on a reload; §2.1) | welcome | none |

**Not in v1:** navigation, tab switches, pull-to-refresh, typing, toggles in settings, sign out, push notifications (sign in is `signedIn` from 1.2). Anything new is added to this table first, in both repos.

## 6. The generator script

Commit at `scripts/feedback-sounds/make_feedback_sounds.py` in the web repo. Run: `python3 scripts/feedback-sounds/make_feedback_sounds.py docs/design/feedback/sounds` (needs `numpy`).

```python
"""Generate Project Planner feedback sounds. Deterministic, no samples, licence-free.
Usage: python3 make_feedback_sounds.py <out_dir>   (needs numpy)"""
import sys, os, wave
import numpy as np

SR = 44100
PEAK = 10 ** (-6 / 20)  # -6 dBFS

def bell(freq, dur, decay=7.0, partials=((1, 1.0), (2.0, 0.30), (3.01, 0.10), (4.2, 0.04))):
    t = np.arange(int(SR * dur)) / SR
    tone = sum(a * np.sin(2 * np.pi * freq * m * t) * np.exp(-decay * m ** 0.5 * t) for m, a in partials)
    return tone * np.minimum(1, t / 0.004)

def glide(f0, f1, dur, decay=18.0):
    t = np.arange(int(SR * dur)) / SR
    f = f0 + (f1 - f0) * (t / dur) ** 0.6
    return np.sin(2 * np.pi * np.cumsum(f) / SR) * np.exp(-decay * t) * np.minimum(1, t / 0.003)

def soft_buzz(freq, dur):
    t = np.arange(int(SR * dur)) / SR
    w = np.sin(2 * np.pi * freq * t) + 0.25 * np.sin(2 * np.pi * 3 * freq * t)
    return w * np.minimum(1, t / 0.006) * np.minimum(1, (dur - t) / 0.03)

def seq(parts, total):
    out = np.zeros(int(SR * total))
    for start, sig, gain in parts:
        i = int(SR * start); n = min(len(sig), len(out) - i)
        out[i:i + n] += gain * sig[:n]
    return out

def finish(x):
    fade = int(SR * 0.02)
    x[-fade:] *= np.linspace(1, 0, fade)
    return x / np.max(np.abs(x)) * PEAK

SOUNDS = {
    'success':  seq([(0, bell(659.25, .32), 1), (.075, bell(987.77, .30), .8)], .40),
    'sent':     glide(520, 820, .16),
    'approved': seq([(0, bell(523.25, .5), .9), (.07, bell(659.25, .5), .85), (.14, bell(783.99, .5), .8), (.21, bell(1046.5, .45), .6)], .62),
    'resolved': seq([(0, bell(783.99, .32, 8), 1), (.09, bell(587.33, .36, 8), .85)], .46),
    'removed':  bell(440, .24, 12, ((1, 1.0), (2.0, .15))),
    'error':    seq([(0, soft_buzz(220, .09), 1), (.15, soft_buzz(196, .11), 1)], .28),
    'queued':   bell(880, .09, 30, ((1, 1.0),)),
}

def write(path, x):
    with wave.open(path, 'wb') as w:
        w.setnchannels(1); w.setsampwidth(2); w.setframerate(SR)
        w.writeframes((np.clip(x, -1, 1) * 32767).astype('<i2').tobytes())

if __name__ == '__main__':
    out = sys.argv[1] if len(sys.argv) > 1 else '.'
    os.makedirs(out, exist_ok=True)
    for name, sig in SOUNDS.items():
        x = finish(np.array(sig, dtype=float))
        write(os.path.join(out, f'pp-{name}.wav'), x)
        print(f'pp-{name}.wav  {len(x)/SR*1000:.0f} ms')
```

## 7. Proof it changes nothing (both platforms)

- **Additive only:** the feedback call goes **after** the existing success or refusal handling. No save payload, store, calculation, permission, route or navigation destination changes (platform guardrail 7).
- **Prove it:** the same booking, leave request and warning resolve, done before and after, produce identical Firestore documents and identical figures on Daily Overview, the weekly report and timesheets.
- **Feedback can never break an action.** If audio or haptics fail (no audio device, blocked autoplay, missing file), it's swallowed silently and the action carries on.
