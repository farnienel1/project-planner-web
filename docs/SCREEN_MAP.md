# Screen map (web ↔ iOS ↔ rulebook)

Owner safeguard **A** (`docs/OWNER_DECISIONS.md`, 4 Nov). One row per screen, built from the code on `main` (web `a1ce46cf`, iOS `af4432c`), not from memory.

**Every PR that touches a screen updates its row** — the files, the rulebook functions it calls, the ways in, and any ✗. This is how `docs/agent-rules/feature-completeness.md` steps 1–2 (every call site, every way in) are checked: the PR lists the rows it changed under **Screen map rows updated** (`.github/pull_request_template.md`). A new screen gets a new row; a removed screen keeps its row with "removed in #n".

How to read it:
- **Web file(s)** — the route under `app/` and the main component. **iOS file(s)** — the SwiftUI view that is the navigation destination (`Project Planner/Views/…` unless a folder is given).
- **Rulebook functions** — `W:` names imported from `@/lib/canonical` by the page, its components and the feature libraries they import directly (stores and app-wide helpers left out; `+N` = more names). `i:` `CanonicalBusinessEngine.*` calls in the view file itself; where the view leans on a Core store, the store is named. Copy constants (`*_LABEL`, `*_MESSAGE`) are omitted.
- **Ways in** — links, buttons, menus, notifications (`kind` from `notificationDestination`, mapped by web `lib/notifications/notificationHref.ts` and iOS `Navigation/NotificationDeepLink.swift`) and deep links. Web: *Nav* = `lib/navigation/dashboardNavigation.ts`, *QA* = `lib/home/quickActions.ts`, *Create* = `lib/navigation/createMenu.ts`, *Hero* = `lib/dashboard/heroMetrics.ts`, *Help* = `components/help/HelpSupportScreen.tsx`, *Job tabs* = `components/projects/ProjectWorkspaceChrome.tsx`. iOS: *Menu* = `Navigation/MainMenuCatalog.swift`, *Tab n* = `ContentView.swift` tab, *Home* = `HomeView.swift` surface.
- **Notes** — ✗ marks an own calculation or a known gap, with a pointer. **web only** / **iOS only** marks a screen that exists on one platform. A ✗ is a finding, not a fix: fixing it is its own PR.

Pattern used for date ✗s: hard-coded `'Europe/London'` / `LONDON_TIME_ZONE`, `getDay()`, browser-zone date-fns weeks, iOS `Calendar.current` / `TimeZone.current` (`platform-guardrails.md` §2). Calls that pass the organisation zone are not marked. Correction (#266): `londonMidnight` / `londonIsoWeekday` called without a zone use the **open organisation's** zone (`organizationZoneOr`, since 1.9.0), not London — they are not wrong-day ✗s; the London name is a rename follow-up (sweep FU-2). Web hits are listed by `scripts/check-second-calculators.mjs` and its allow-list.
