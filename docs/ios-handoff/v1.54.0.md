## What changed in 1.54.0

- **Switched-off schedule places are paid** (§4.8, §8, owner decision 16 Nov): the timesheet collector and the weekly report no longer leave out Office, Working from home, Site survey and custom-item bookings when that option is switched off (web `includesManagerScheduleLocation` removed). **Pay change** for unsigned timesheets and the weekly report; raise `minimumIosBuild`.
- **Late extras** (§8, §16, owner decision 16 Nov "allow adding after sign-off so they can re-issue"; redesigned before merge after two independent reviews of #337 found pay could be raised after the counter-signature): the signed entries stay closed after the line manager signs (as before; `timesheetOwnerCanAddExtras`, the security rules unchanged for them); the person adds `lateExtras` until export (`timesheetOwnerCanAddLateExtras`), which pay only once a reviewer approves them in `extraEntryReviews` with `lateExtra: true` and the entry's fingerprint (`timesheetLateExtraDecision`, `timesheetLateExtraRows`, `parseTimesheetLateExtras`, `timesheetLateExtrasSnapshotRows`, `timesheetLateExtrasSummary`, `timesheetChangesWithLateExtras`, `timesheetLateExtraLabel`, `TIMESHEET_LATE_EXTRA*` copy; `TimesheetEntryReview.lateExtra`, `timesheetEntryReviewFor`; `timesheetInvoiceRows` adds approved late extras). No signature is cleared. Security rules: the owner may write `lateExtras` unless `exportedAt` is set. Removed from the first draft: `signedTimesheetExtrasChanges`, `signedTimesheetExtrasRecord`, `signedTimesheetExtrasBaselineFields`, `signedTimesheetChanges`, `operativeSignedExtras`, the snapshot-row diffing and the inline-decision trust change.
- **"Your signed timesheet has changed"** (§8, §13, owner decision 16 Nov): new notice type `timesheet_bookings_changed` (push, toggle `timesheetSignOff`, opens My Timesheets), written by two new Cloud Functions on booking writes; `timesheetBookingChangeNotice`, `timesheetBookingWriteMatters`, `timesheetBookingsChangedRecipients`, `timesheetBookingsChangedNoticeId`, `TIMESHEET_BOOKINGS_CHANGED_NOTICE_*`. Replaces the 1.47.0 "no notification is sent".
- **Review of #337 fixes** (before merge): the notice shares the app's decision (`signedTimesheetBookingWriteReopens`) and queries only the sheets covering the booking day (new composite index `settings` userId + weekEnd); switched-off places never repair a signed snapshot (`scheduleOptionPlace`); `timesheetExportedFieldSet` (the stored `exportedAt` the rules test); Data health checks the last six pay runs and links to the sheet.
- **Annual leave report = the balance's leave year** (§9, owner decision 16 Nov, web Annual leave report parity with iOS; review of web PR #335): new `annualLeaveReportYearMonths` (the months `annualLeaveBalance` uses — the person's own leave year with an allowance, else the organisation's), passed to `leaveReportRows` / `leaveReportYears`; "Holiday Report" renamed "Annual leave report" in §9. iOS `HolidayReportView` must call it.
- **Data health "Timesheets half signed"** (§8, owner decision 16 Nov, (a) + (c)): `timesheetsHalfSigned`, `TIMESHEETS_HALF_SIGNED_HEADING` / `_HELP` / `_NONE`. Read only.
- **Third review of #337** (before merge): (1) a late extra whose id is a signed entry's (another letter case) is flagged and never reviewed — `timesheetLateExtraReviewable`, `TIMESHEET_LATE_EXTRA_ID_TAKEN_LABEL`, `timesheetLateExtraLabel` takes the reason; `timesheetEntryReviewWriteFields` never writes a late review under a signed entry's key (new `signedEntryIds`) or across kinds, and `timesheetEntryDecision` never reads a `lateExtra` review as a signed entry's (before: approving late `e1` replaced signed `E1`'s declined £1000 review, so £1000 read as pending); late fingerprints under their own key (`timesheetLateExtraFingerprintKey`, `timesheetLateExtraFingerprintMap`). (2) An exported sheet's late extras are frozen: no review offered or written (`exported`), and a sheet with late extras is not re-priced after export; rules refuse reviewer changes to `extraEntryReviews` / `weeklyReportOverride` once `exportedAt` is stored on a sheet with late extras. (3) Export stamps only `weeklyReportOverride` and `exportedAt` in a transaction that refuses when late extras now wait. (4) The reviewer's save writes the sheet and its reviews in one update; the weekly report feed counts a snapshot's late rows only while still approved (`timesheetSnapshotMoneyRowsCurrent`). (5) Rules: `lateExtras` only after the line manager signs. Static compile cost 229,698 → 229,929.
- **Fourth review of #337** (before merge): (1) a late extra whose id matches a signed entry's derived id (`timesheetEntryId`, without case) or cannot be a review key is ignored, never pending — `timesheetSignedEntryKeys`, `timesheetEntryReviewKeyUsable`, `TIMESHEET_LATE_EXTRA_ID_UNUSABLE_LABEL`, `timesheetLateExtraDecision` / `timesheetLateExtraRows` / summary take `sheetDocId`. (2) Rules: once `exportedAt` is stored no reviewer writes `lateExtras`. (3) `timesheetEntryReviewWriteFields` derives the signed ids itself (`sheet`, `sheetDocId`); a signed entry matching a stored late review only without case writes under its own id. (4) Rules: `lateExtras` stored as `null` counts as none. (5) The period page totals and the weekly report check line drop a snapshot late row once that late extra is no longer approved at that amount (web `draftWithCurrentLateRows`). Static compile cost 229,929 → 229,967.
- **Final check of #337** (before merge): (1) one shared row test, `timesheetLateExtraRowProblem` — an id that is over `TIMESHEET_ENTRY_ID_MAX_LENGTH` (200) or a reserved `__…__` name (`timesheetEntryReviewKeyUsable`), or a blank title, is ignored (reason `no-title` / `id-unusable`) in the reader, rows, summary and writer; of two rows with one id the first wins in `parseTimesheetLateExtras` too. (2) Rules: no reviewer removes or changes a stored `exportedAt`. (3) Rules: the owner writes `lateExtras` only as a list or null. (4) The writer compares `(prior.lateExtra === true) !== late`. Static compile cost 229,967 → 230,035.
