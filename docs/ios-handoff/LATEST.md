## What changed in 1.33.0

- **PAYE overtime: Send → Return** (§25, §13, owner decisions 6 Nov). One state machine for ✓ ✕ ⚙ (`overtimeChoiceAfter`, `overtimeChoiceView`); each button's readiness is a rule: **Send for approval** (`overtimeSubmitReady`, `overtimeSubmitLines`; after a Return grey until the person changes a line, and only changed lines are sent), **Return overtime** (`overtimeReturnReady`) and **Generate overtime report** (`overtimeGenerateReady`). Return is the only action that writes the bookings and reviews, in one transaction (`overtimeReturnWrites`, replacing `overtimeApprovalWrites`, `overtimeRequestAnyDecided` and the 1.32 partial approval): ✓ applies the person's line, ⚙ + ✓ the decider's values, ✕ means "I don't agree with this line at all" and leaves the booking as it was; a line changed since it was sent goes back to the person (skip-and-name, `staleBookingIds`). New line states (confirmed, returned approved / changed / declined, reopened, deleted); the person hears "Your line manager {name} has returned your overtime request". A booking changed after Send, Return or a report reopens its line and notifies the person (and their line manager when it had been returned); a saved report is then **Out of date** and Generate turns green again. A line still declined at Generate is in the report at 0h, "Declined by {name}". The person's red X on an all-overtime day now **deletes** the booking (with a tombstone naming the request), never cancels it (`OVERTIME_DELETE_WARNING`).
- **A line manager can always approve** (§16, §25, §26, owner 6 Nov): overtime lines and price work / expense items under every id the person goes by (`overtimePersonIds`, `operatives` rows on their email); no "Needs an admin" (`OVERTIME_NEEDS_ADMIN_LABEL`, `OVERTIME_NEEDS_ADMIN_MESSAGE` removed). Claim items carry `personUserId` (`payeClaimPersonFields`); older items get it from a backfill (`payeClaimPersonUserIdBackfill`, Deploy notes). `reviewApprovalMessage` moves to `payeClaimReviews.ts` (claims only).
- **Bookings: no Cancel** (§2, owner 4 Nov): Book / Edit / Delete only; every remove control asks `bookingRemoveAction` (exactly the `canDeleteBooking` people); `booking.cancel` leaves the offline table; stored `Cancelled` bookings stay hidden. **Offline delete on iOS / Android** (`booking.delete` offline, `booking.delete_subcontractor` online only, `offlineDeleteReplayDecision`, `bookingDeleteFingerprint`, `bookingDeleteSignedTimesheetWarning`). Tombstones may carry `overtimeRequestId`.
- **Every manager sees every project, small works job and booking** (§17, §21, owner 6 Nov): `seesEveryJob`, `canSeeJob`, `readsEveryBooking` true for managers outside operative mode; the Projects / Small works toggles now govern adding jobs and changing manager lists only. The managers' per-job hide list is gone; the **operatives' hide list stays** (the job's View page shows only "Hide this job from these operatives"). New **My Projects / My Small works** filter, the default for admins and managers (`myWorks*`, picks in `worksListPicks/{uid}`). A manager's **Daily Overview** shows only themselves and their reports (`dailyOverviewScopeFor`, §6). Any manager may send a materials request for any job (owner 6 Nov).
- **Line manager set once, then locked** (§11, §16): `canChangeLineManager`, `lineManagerChanged`; an Operatives manager sets it only when adding an operative or on their own unaccepted invitation; afterwards only admins.
- **Payrun Snapshot** (§7): the Weekly report's admin-only button and period picker; one row per person with Timesheet, Overtime, Expenses and Price work cells (`payrunSnapshotPeriods`, `payrunSnapshotRows`); an overtime report counts only while its live lines still match it. **Report PDFs** look like the invoice report (`overtimeReportRows`, `payeClaimReportRows`, `payeClaimEvidencePages`, `reportGeneratedText`).
- **Smaller fixes**: materials catalogue admins only (`canManageMaterialCatalogue`); `userActiveWrites` never writes another company's users document and never creates a membership; an inactive account is never picked for an `operatives` row in unbooked labour (`preferFinishedAccount`); pay visibility stays option C1 (tests only).
- **Security rules** (§16): every staff member reads every job and booking; overtime Return keys and review decisions; the line manager writes and (on Return) deletes bookings under the person's own `operatives` row; claim items and reviews with `personUserId`; `worksListPicks`; the line-manager lock; materials catalogue admins only. Compile cost 232,589 (1.32.4: 234,347), on top of 1.32.4's custom-claims role checks.
