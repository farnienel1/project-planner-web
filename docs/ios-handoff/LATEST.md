## What changed in 1.48.0

- **Materials quantity model** (new §28, owner decisions 15 Nov 1–5; new `lib/canonical/materialQuantity.ts`): order units `MATERIAL_ORDER_UNITS` (Each, Box, Pack, Drum, Reel, Coil, Pallet, Length, Metre) with what is in one (`contentAmount` + `contentMeasure` m / mm / pcs), `MATERIAL_ORDER_UNIT_DETAILS`, the reader `materialQuantityModel` (old Length + 1 m reads as Metre; Number → Each; float noise and glued units tidied), the writer `materialQuantityWriteFields` (new fields plus the nearest old meaning), `materialQuantityError` (whole numbers except Metre) and `materialContentError`.
- **One wording** `materialLineText` (UK trade style: "2no 50m drums", "1no 50m drum", "10no 3m lengths", "2no boxes of 100", "4no", "100m", "12.5m"; no pack totals) on every screen, the email (web and the function), WhatsApp and new send records (`quantityText`); past send records keep their wording (`materialSendLineText`). `materialSizeText` hides the Size "1.0" placeholder (display only).
- **Readers and writers**: `parseMaterialLineDocument` / `parseMaterialCatalogueDocument` return `orderUnit`, `contentAmount`, `contentMeasure` (a line also `quantityText`); `materialLineFields` / `materialCatalogueItemFields` take them and write the old fields too; `materialLineWriteFields` / `materialCatalogueItemWriteFields` keep a pre-1.48.0 document's quantity fields when its meaning is unchanged; a stored `orderUnit` is read only while the stored old fields agree with it (an older build's edit of the old fields wins); `parseMaterialSendRecordDocument` / `materialSendRecordCreateFields` read and write `quantityText`. `materialWhatsAppRows` lines read "• Pipe — 2no 3m lengths · Code P1". `materialQuantityLabel` is kept for history only. Cross-platform contract: the web material line and catalogue samples carry the new fields.
- **Catalogue CSV** (new `lib/canonical/materialCatalogueCsv.ts`, web and iOS): new columns Order unit, Contents amount, Contents measure (old columns still import, by header name, and are appended to every export with the nearest old meaning); upload safety — .csv only, 2 MB, 10,000 rows, UTF-8 with no NUL or binary characters, field caps, plain text, parsed on the device and never uploaded; export neutralises formulas (`materialCatalogueCsvCell`).
- **Built-in starter catalogue** rebuilt in the new model from the owner's organisation export (`scripts/materials/build-starter-catalogue.ts`): 4,037 items (4,032 before + 5 owner-added real products), 16 test / junk rows dropped, "Unknown" / "Custom" brand → blank, 44 lengths with float noise fixed, 2,806 Size "1.0" placeholders removed, 95 "Length + 1 m" items now Metre and 35 fixed "- 1m" pieces Length with 1 m in one; existing Catalogue IDs kept; still seeded only into an empty catalogue.
- Web: catalogue editor and job Add material use the order-unit picker with "What's in one" (`components/materials/OrderUnitFields.tsx`); lists, send sheet, history, email and WhatsApp print `materialLineText`; web's "m / mm / kg" line units are gone (stored ones read as Metre / Each). Dead `formatLengthSpecification` and `quantityLabel` removed.
- No security rules change. Functions deploy (email) needed.
