## What changed in 1.47.0

- **A signed timesheet reopens when its bookings change** (§8, owner decision 15 Nov, answer 4.2 = (a); new `lib/canonical/timesheetBookingChanges.ts`): `signedTimesheetBookingChanges` compares what was signed (`operativeSignedBookings` when it belongs to the latest signature, else the signed snapshot's lines) with the period's live payroll lines and the booking documents. Reopens only for a real booking change: a signed booking's day, slot, times, overtime rate, break toggle (the fingerprint without status — Tentative ↔ Confirmed is not a change) or job / place (`signedTimesheetBookingPlace`); a signed booking deleted, tombstoned, no longer occupying its day (`bookingOccupiesDay`: Cancelled, Declined, unknown) or now stored under an id outside every id the person goes by (`personIds`) — judged from the booking document, never from the collector's filters, so switching a schedule option off or an email / `operatives` row change never reopens a sheet; a booking added after the signature (by its write time against the record's server time, less a 10-minute window; no write time never counts). PAYE-day and leave lines never count. Not exported: back for signing (`waitingFor` person, then line manager); exported: frozen, a warning for the reviewer only. Derived, never written by the booking's editor; no security rules change. Sheets signed before 1.46.0 (no fingerprints) reopen only for a deleted, cancelled or added booking, never for hours.
- New: `signedTimesheetBookingRecord` (stored as `operativeSignedBookings` with every operative signature, with `operativeSignedBookingsSignedAt` and the server-time `operativeSignedBookingsAt`; each row `{ bookingId, collection, fingerprint, personId, place }`), `signedTimesheetBookingPlace`, `SIGNED_TIMESHEET_ADDITION_WINDOW_MS`, `signedTimesheetActions` (no export or invoice while reopened; counter-sign again once the person has signed; `rebuildSnapshot`), `signedTimesheetLineBookingKey`, `SignedTimesheetBookingDocument`, `SIGNED_TIMESHEET_CHANGED_MESSAGE` (the owner's popup text), `SIGNED_TIMESHEET_CHANGED_LABEL`, `SIGNED_TIMESHEET_CHANGED_STATUS`, `SIGNED_TIMESHEET_CHANGED_REVIEWER_MESSAGE`, `SIGNED_TIMESHEET_CHANGED_COUNTERSIGN_MESSAGE`, `SIGNED_TIMESHEET_EXPORTED_CHANGED_MESSAGE`, `SIGNED_TIMESHEET_EXPORT_SKIPPED_MESSAGE`.
- `timesheetListBucket(fields, hasLineManager, change?)`: a reopened sheet reads `unsigned` (waiting for the person) or `awaiting` (waiting for the line manager); exported stays exported; without `change` unchanged. `PayrunSnapshotSheet.bookingsChange` passes it to the Payrun Snapshot.
- `BOOKING_DELETE_SIGNED_TIMESHEET_WARNING` now says an unexported sheet goes back to the person to sign again and an exported one does not change.
- Web: the yellow triangle and popup on the Timesheets hub's My timesheets entry and on the changed row / current period on My Timesheets; "Review and sign again" (only once bookings, pay inputs, schedule options, operatives and roster have loaded); the line manager's review blocks counter-signing while the person must sign again and offers counter-signing again after; counter-signing (and a self-signed re-signature) rebuilds the snapshot from the live bookings; a reopened sheet's figures are live; User Timesheets lists, hub counts, the own-sheet export notice, Export (skipped with a reason), the weekly report feed and the Payrun Snapshot follow the rule. The hub checks the last six pay runs and loads bookings only from the earliest of their starts; the feed and the Payrun Snapshot read a sheet as changed only when the loaded bookings hold its whole pay run.
- Owner answers recorded (`docs/OWNER_DECISIONS.md`): the 0.05h (3-minute) overtime cut-off stays (bookings and the working day are on 15 / 30-minute steps, so it cannot arise for new data); Edit hours stays editable after sign-off (option (b)).
- Tooling: the iOS hand-off lists only the exports really added or removed (`scripts/rulebook-sync.mjs` read the previous packed script with a 1 MB buffer, so every export was listed as added).
- No security rules change.

## iOS work for 1.47.0

**Sync first.** 1.47.0 (owner decision 15 Nov, answer 4.2 = (a)): **a signed timesheet reopens when its bookings change.** When a booking on a signed timesheet changes and the sheet is **not exported**, the sheet goes back for signing: the person signs the live bookings again, then the line manager counter-signs again. An **exported** sheet stays frozen; its reviewer only sees a warning. No Firestore rules, Storage rules, index or Functions change. **Stored shape change (optional, owner fields):** `settings/timesheet_*` gains `operativeSignedBookings: [{ bookingId, collection, fingerprint, personId, place }]`, `operativeSignedBookingsSignedAt` (the same value as that `operativeSignedAt`) and `operativeSignedBookingsAt` (**`FieldValue.serverTimestamp()`**, never the device clock), written together with every operative signature. **iOS must read it and keep it on every write of the sheet** (sign, re-sign, counter-sign, re-apply, export, any save) — never drop it, never write it for someone else's sheet. Line numbers are from iOS `origin/main` as read on 15 Nov; check them on your branch.

1. **Sync** — `WEB_REPO=<web worktree> bash scripts/sync-rulebook-from-web.sh`, commit the mirrored files.
2. **Bind the new functions** in `Project Planner/Canonical/CanonicalBusinessEngine.swift` (next to `timesheetListBucket` ~2168): `signedTimesheetBookingChanges({ sheet, liveLines, liveBookings, tombstonedBookingIds, personIds, liveLoaded, selfSigned })` → `{ changed, exported, reopened, waitingFor ("person" | "lineManager" | null), basis, changedBookingIds, addedBookingIds, removedBookingIds, message, reviewerMessage }`; `signedTimesheetBookingRecord(liveLines, liveBookings)` → `[{ bookingId, collection, fingerprint, personId, place }]`; `signedTimesheetBookingPlace(doc)`; `signedTimesheetActions(change)` → `{ personMaySignAgain, lineManagerMayCounterSign, mayExport, mayGenerateInvoice, rebuildSnapshot }`; and give `timesheetListBucket` its new optional third argument `change` (`{ reopened, waitingFor }`). Read the texts from the script, never retype them: `SIGNED_TIMESHEET_CHANGED_MESSAGE`, `SIGNED_TIMESHEET_CHANGED_LABEL`, `SIGNED_TIMESHEET_CHANGED_STATUS`, `SIGNED_TIMESHEET_CHANGED_REVIEWER_MESSAGE`, `SIGNED_TIMESHEET_CHANGED_COUNTERSIGN_MESSAGE`, `SIGNED_TIMESHEET_EXPORTED_CHANGED_MESSAGE`, `SIGNED_TIMESHEET_EXPORT_SKIPPED_MESSAGE`. **No comparison in Swift**: never compare fingerprints, booking ids or hours yourself.
3. **Inputs** — `sheet`: the stored sheet fields `operativeSignedAt`, `operativeSignedBookings`, `operativeSignedBookingsSignedAt`, `operativeSignedBookingsAt`, `managerSignedAt`, `approvedAt`, `exportedAt`, `invoiceGeneratedAt` and `weeklyReportOverride` (`approvedAt` and `lines` with each line's `id`, `bookingId`, `bookingFingerprint`, `isPayeDay`, `isLeave`, `reviewPartOf`). `liveLines`: the period's lines from `Core/TimesheetPayrollCollector.swift` for that person, each with `id`, `bookingId`, `bookingCollection`, `bookingFingerprint` (1.46.0: from `overtimeBookingFingerprint`), `isPayeDay`, `bookingCreatedAt`, `bookingUpdatedAt` (needed: a booking counts as added only when written after the signature) — leave lines are not passed (or pass `isLeave: true`). `liveBookings`: **every** labour and manager site booking document loaded for at least the whole pay run (anyone's, not only this person's), each `{ bookingId, collection, dayKey (organisation zone), timeSlot, workStartTime, workEndTime, isBreakRemoved, otMultiplierOverride, status (as stored; manager site bookings have none), personId (labour `operativeId`, manager site `userId`), projectId (labour), locationType / locationId / customLocationName (manager site) }` — this is what decides that a signed booking no longer on the sheet was deleted, cancelled, moved or given to someone else. **Never decide removals from the collector's lines**: a schedule option switched off, an email or `operatives` row change, or a PAYE day only filters a booking out and must not reopen a sheet (review #325 blockers). `tombstonedBookingIds` (`{ collection, bookingId }`) if iOS has them (optional). `personIds`: every id the person's bookings may be stored under (`bookingIdsForAccount` — users id, former ids, same-email ids, `operatives` rows on their email); without it a booking is never read as given to someone else. `liveLoaded`: the bookings have arrived from the server **and the loaded window holds the whole pay run** (the 1.43.0 `timesheetSnapshotReady` gate); pass false otherwise — nothing reads as changed then. `selfSigned`: `timesheetSelfSigned(person, roster)`.
4. **Store what the person signed** — at the operative signature (`Views/InvoicingView.swift` ~2438, `draft.operativeSignedAt = Date()`), set `operativeSignedBookings = signedTimesheetBookingRecord(liveLines, liveBookings)` from the same live lines the screen shows `operativeSignedBookingsSignedAt` = exactly the `operativeSignedAt` value written, and `operativeSignedBookingsAt` = `FieldValue.serverTimestamp()` (written once, with the signature — never re-stamped by later saves; while it is pending the rule compares against the signature time less 10 minutes), and write them with the signature (owner write; `timesheetOwnerWriteFields` keeps them). **Only once every input has loaded** — the period's bookings, the pay inputs and organisation settings (schedule options included), the operatives catalogue and the roster; otherwise keep Sign disabled. A record older than the latest signature is ignored by the rule, so every signature must write a fresh one. Add the three fields to `TimesheetDraft` (`Models/TimesheetDraftModels.swift`), `asFirestoreMap` (~1188) and the reader (~1242): `operativeSignedBookings` an array of `{ bookingId, collection, fingerprint, personId, place }` strings, the two `…At` timestamps; missing = nil (sheets signed before 1.47.0). `clearSignatures` clears all three with the signature.
5. **My Timesheets — the owner's UI** (`Views/InvoicingView.swift`): a small **yellow** warning triangle (SF Symbol `exclamationmark.triangle.fill`, yellow / system yellow so it reads in light and dark mode) with the accessibility label `SIGNED_TIMESHEET_CHANGED_LABEL`:
   - next to **"My Timesheets"** on the Timesheets hub tile / menu entry (~328 and the manager tile ~407) when any of the person's signed, unexported sheets has `waitingFor == "person"`;
   - on the **My Timesheets** page (`MyTimesheetsHubView` ~1577) next to that timesheet's row (and the current pay-run card when it is the current period); the row goes in Pending with the chip `SIGNED_TIMESHEET_CHANGED_STATUS`.
   Tapping the triangle opens a small alert / popover with exactly `SIGNED_TIMESHEET_CHANGED_MESSAGE` ("One or more bookings have changed since you signed your timesheet. Please review and sign again, or speak to your line manager if something isn't correct.") and an OK button. Only the person's own sheets show it; an exported sheet never does.
6. **The sheet** — while `waitingFor == "person"` the person's sheet shows the same message and offers "Review and sign again" (the normal sign flow, writing a new signature and step 4's record); the old manager signature is not shown as signing it off. A sheet with `reopened` shows the **live** bookings' figures: give `timesheetTotals` / `timesheetInvoiceRows` the sheet **without** `weeklyReportOverride` (web `draftForFigures`); never show, invoice or export the stale snapshot. Generate Invoice is off while `signedTimesheetActions(change).mayGenerateInvoice` is false.
7. **Line manager's review** (`OperativeTimesheetReviewView` and the counter-sign path ~930–955): while `waitingFor == "person"` show `reviewerMessage` and **no** counter-sign; when `waitingFor == "lineManager"` show `reviewerMessage` and offer counter-sign **again** even though `managerSignedAt` is stored. That counter-signature (and a self-signed person's re-signature) **rebuilds the snapshot from the live bookings** (`rebuildSnapshot`: in `Core/TimesheetWeeklyReportOverrideBuilder.swift` build it fresh as at first approval, with the new signatures, instead of re-applying reviews to the stored lines). Never rebuild an exported sheet. An exported sheet with `changed` shows `reviewerMessage` (`SIGNED_TIMESHEET_EXPORTED_CHANGED_MESSAGE`) only.
8. **Lists, counts, export** — every Awaiting / Signed off / Exported decision passes the sheet's change to `timesheetListBucket(fields, hasLineManager, change)` (`InvoicingView.swift` ~920, the hub tile counts, User Timesheets lists): reopened + person → `unsigned`, reopened + line manager → `awaiting`, exported stays `exported`. `exportSignedTimesheets` (~4008) skips any sheet whose `signedTimesheetActions(change).mayExport` is false (re-check on the freshly read sheet before stamping `exportedAt`) and names it with `SIGNED_TIMESHEET_EXPORT_SKIPPED_MESSAGE`. The own-sheet export notice treats a sheet waiting for the person as not signed.
9. **Payrun Snapshot** (`Views/PayrunSnapshotView.swift` ~215, `Core/Rulebook+PayrunSnapshot.swift`): pass each sheet's `{ reopened, waitingFor }` as `bookingsChange` on the sheet (Not started / Submitted follow it) when the loaded bookings hold that sheet's pay run — web does (`lib/weekly-report/payrunSnapshotData.ts`, `components/weekly-report/PayrunSnapshot.tsx`).
9a. **Hub cost** — for the triangle on the My Timesheets tile, check only the last 6 pay runs' signed, unexported sheets, load bookings only from the earliest of their starts (not the whole archive), and compute each sheet's change once per period (web `TimesheetsHub.tsx` `HUB_CHANGE_SCAN_RUNS`, `periodBookingChanges` memo).
10. **Weekly report feed** (`Core/WeeklyReportTimesheetFeed.swift`): a fully signed sheet whose change is `reopened` is not an approved week — report its live bookings (web `lib/weekly-report/loadTimesheetFeed.ts`). Pass `liveLoaded` true only when the loaded bookings hold that sheet's whole pay run.
11. **Booking delete warning** — `BOOKING_DELETE_SIGNED_TIMESHEET_WARNING` changed text ("…If it has not been exported, it goes back to the person to review and sign again. An exported timesheet does not change."); `Core/Rulebook+OfflineDelete.swift` reads it from the script — no Swift copy of the old text.
12. **No notification** is sent when a signed sheet's bookings change (owner question open).
13. **Tests** — through the script: an unchanged sheet → not changed; a booking's end time changed → `reopened`, `waitingFor == "person"`, the owner text; a booking added after the signature / deleted / cancelled → reopened; **Office switched off in schedule options (the collector drops the manager site booking, its document unchanged) → not reopened**; **the person's `operatives` row unlinked / email changed (the collector no longer finds the booking, its document unchanged) → not reopened**; the booking given to another person → reopened, rewritten from the person's operatives row to their users id → not; Tentative → Confirmed → not changed; Declined / unknown status → removed; a job or place change → reopened; OT rate or break toggle change → reopened; an Edit hours part (`reviewPartOf`) alone → not; labour → manager site move → removed + added; a booking written 5 min before a fast device's signature → added; PAYE-day lines → never counted; a record older than the signature → ignored; exported → `exported`, `reopened == false`, bucket `exported`; a sheet signed before 1.46.0 (snapshot lines without `bookingFingerprint`) → only added / removed bookings reopen it, never hours; `CUSTOM` (web) vs `CUSTOM_HOURS` (iOS) → not changed; after the person re-signs (record = live) → `waitingFor == "lineManager"`, bucket `awaiting`; `operativeSignedBookings` round-trips through `asFirestoreMap` / the reader.
