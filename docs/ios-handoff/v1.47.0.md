## What changed in 1.47.0

- **A signed timesheet reopens when its bookings change** (§8, owner decision 15 Nov, answer 4.2 = (a); new `lib/canonical/timesheetBookingChanges.ts`): `signedTimesheetBookingChanges` compares what was signed (`operativeSignedBookings`, else the signed snapshot's lines) with the period's live payroll lines — booking fingerprints with `overtimeFingerprintsMatch`, plus added and removed bookings. Not exported: the sheet is back for signing (`waitingFor` person, then line manager); exported: frozen, a warning for the reviewer only. Derived, never written by the booking's editor; no security rules change. Sheets signed before 1.46.0 (no fingerprints) reopen only for an added or removed booking, never for hours; signed lines naming no booking, a pre-1.47.0 person signature with no snapshot, and unloaded bookings never read as changed.
- New: `signedTimesheetBookingRecord` (stored as `operativeSignedBookings` with every operative signature), `signedTimesheetActions` (no export or invoice while reopened; counter-sign again once the person has signed; `rebuildSnapshot`), `signedTimesheetLineBookingKey`, `SIGNED_TIMESHEET_CHANGED_MESSAGE` (the owner's popup text), `SIGNED_TIMESHEET_CHANGED_LABEL`, `SIGNED_TIMESHEET_CHANGED_STATUS`, `SIGNED_TIMESHEET_CHANGED_REVIEWER_MESSAGE`, `SIGNED_TIMESHEET_CHANGED_COUNTERSIGN_MESSAGE`, `SIGNED_TIMESHEET_EXPORTED_CHANGED_MESSAGE`.
- `timesheetListBucket(fields, hasLineManager, change?)`: a reopened sheet reads `unsigned` (waiting for the person) or `awaiting` (waiting for the line manager); exported stays exported; without `change` unchanged. `PayrunSnapshotSheet.bookingsChange` passes it to the Payrun Snapshot.
- `BOOKING_DELETE_SIGNED_TIMESHEET_WARNING` now says an unexported sheet goes back to the person to sign again and an exported one does not change.
- Web: the yellow triangle and popup on the Timesheets hub's My timesheets entry and on the changed row / current period on My Timesheets; "Review and sign again"; the line manager's review blocks counter-signing while the person must sign again and offers counter-signing again after; counter-signing (and a self-signed re-signature) rebuilds the snapshot from the live bookings; a reopened sheet's figures are live; User Timesheets lists, hub counts, export and the weekly report feed follow the rule.
- Owner answers recorded (`docs/OWNER_DECISIONS.md`): the 0.05h (3-minute) overtime cut-off stays (bookings and the working day are on 15 / 30-minute steps, so it cannot arise for new data); Edit hours stays editable after sign-off (option (b)).
- No security rules change.

   Tapping the triangle opens a small alert / popover with exactly `SIGNED_TIMESHEET_CHANGED_MESSAGE` ("One or more bookings have changed since you signed your timesheet. Please review and sign again, or speak to your line manager if something isn't correct.") and an OK button. Only the person's own sheets show it; an exported sheet never does.
6. **The sheet** — while `waitingFor == "person"` the person's sheet shows the same message and offers "Review and sign again" (the normal sign flow, writing a new signature and step 4's record); the old manager signature is not shown as signing it off. A sheet with `reopened` shows the **live** bookings' figures: give `timesheetTotals` / `timesheetInvoiceRows` the sheet **without** `weeklyReportOverride` (web `draftForFigures`); never show, invoice or export the stale snapshot. Generate Invoice is off while `signedTimesheetActions(change).mayGenerateInvoice` is false.
7. **Line manager's review** (`OperativeTimesheetReviewView` and the counter-sign path ~930–955): while `waitingFor == "person"` show `reviewerMessage` and **no** counter-sign; when `waitingFor == "lineManager"` show `reviewerMessage` and offer counter-sign **again** even though `managerSignedAt` is stored. That counter-signature (and a self-signed person's re-signature) **rebuilds the snapshot from the live bookings** (`rebuildSnapshot`: in `Core/TimesheetWeeklyReportOverrideBuilder.swift` build it fresh as at first approval, with the new signatures, instead of re-applying reviews to the stored lines). Never rebuild an exported sheet. An exported sheet with `changed` shows `reviewerMessage` (`SIGNED_TIMESHEET_EXPORTED_CHANGED_MESSAGE`) only.
8. **Lists, counts, export** — every Awaiting / Signed off / Exported decision passes the sheet's change to `timesheetListBucket(fields, hasLineManager, change)` (`InvoicingView.swift` ~920, the hub tile counts, User Timesheets lists): reopened + person → `unsigned`, reopened + line manager → `awaiting`, exported stays `exported`. `exportSignedTimesheets` (~4008) skips any sheet whose `signedTimesheetActions(change).mayExport` is false (re-check on the freshly read sheet before stamping `exportedAt`).
9. **Payrun Snapshot** (`Views/PayrunSnapshotView.swift` ~215, `Core/Rulebook+PayrunSnapshot.swift`): pass each sheet's `{ reopened, waitingFor }` as `bookingsChange` on the sheet when the period's bookings and pay inputs are loaded (Not started / Submitted follow it); web does not wire this yet (a follow-up), so leave it out if it would need new loading on iOS.
10. **Weekly report feed** (`Core/WeeklyReportTimesheetFeed.swift`): a fully signed sheet whose change is `reopened` is not an approved week — report its live bookings (web `lib/weekly-report/loadTimesheetFeed.ts`).
11. **Booking delete warning** — `BOOKING_DELETE_SIGNED_TIMESHEET_WARNING` changed text ("…If it has not been exported, it goes back to the person to review and sign again. An exported timesheet does not change."); `Core/Rulebook+OfflineDelete.swift` reads it from the script — no Swift copy of the old text.
12. **No notification** is sent when a signed sheet's bookings change (owner question open).
13. **Tests** — through the script: an unchanged sheet → not changed; a booking's end time changed → `reopened`, `waitingFor == "person"`, the owner text; a booking added / removed → reopened; exported → `exported`, `reopened == false`, bucket `exported`; a sheet signed before 1.46.0 (snapshot lines without `bookingFingerprint`) → only added / removed bookings reopen it, never hours; `CUSTOM` (web) vs `CUSTOM_HOURS` (iOS) → not changed; after the person re-signs (record = live) → `waitingFor == "lineManager"`, bucket `awaiting`; `operativeSignedBookings` round-trips through `asFirestoreMap` / the reader.
14. **minimumIosBuild** — the owner raises it to the iOS 1.47 build before web 1.47 merges (Deploy notes 1.47.0): an older iPhone shows a changed sheet as signed off and its line manager can still export the stale snapshot.
