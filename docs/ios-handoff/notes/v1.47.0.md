**Sync first.** 1.47.0 (owner decision 15 Nov, answer 4.2 = (a)): **a signed timesheet reopens when its bookings change.** When a booking on a signed timesheet changes and the sheet is **not exported**, the sheet goes back for signing: the person signs the live bookings again, then the line manager counter-signs again. An **exported** sheet stays frozen; its reviewer only sees a warning. No Firestore rules, Storage rules, index or Functions change. **Stored shape change (optional, owner field):** `settings/timesheet_*` gains `operativeSignedBookings: [{ bookingId, collection, fingerprint }]`, written with every operative signature. **iOS must read it and keep it on every write of the sheet** (sign, re-sign, counter-sign, re-apply, export, any save) — never drop it, never write it for someone else's sheet. Line numbers are from iOS `origin/main` as read on 15 Nov; check them on your branch.

2. **Bind the new functions** in `Project Planner/Canonical/CanonicalBusinessEngine.swift` (next to `timesheetListBucket` ~2168): `signedTimesheetBookingChanges({ sheet, liveLines, liveLoaded, selfSigned })` → `{ changed, exported, reopened, waitingFor ("person" | "lineManager" | null), basis, changedBookingIds, addedBookingIds, removedBookingIds, message, reviewerMessage }`; `signedTimesheetBookingRecord(liveLines)` → `[{ bookingId, collection, fingerprint }]`; `signedTimesheetActions(change)` → `{ personMaySignAgain, lineManagerMayCounterSign, mayExport, mayGenerateInvoice, rebuildSnapshot }`; and give `timesheetListBucket` its new optional third argument `change` (`{ reopened, waitingFor }`). 3. **Inputs** — `sheet`: the stored sheet fields `operativeSignedAt`, `operativeSignedBookings`, `managerSignedAt`, `approvedAt`, `exportedAt`, `invoiceGeneratedAt` and `weeklyReportOverride` (`approvedAt` and `lines` with each line's `id`, `bookingId`, `bookingFingerprint`, `isPayeDay`, `isLeave`, `reviewPartOf`). `liveLines`: the period's lines from `Core/TimesheetPayrollCollector.swift` for that person, each with `id`, `bookingId`, `bookingCollection`, `bookingFingerprint` (1.46.0: from `overtimeBookingFingerprint`), `isPayeDay`, `bookingCreatedAt`, `bookingUpdatedAt` — leave lines are not passed (or pass `isLeave: true`). `liveLoaded`: the period's bookings have arrived from the server (the 1.43.0 `timesheetSnapshotReady` gate); pass false otherwise — nothing reads as changed then. `selfSigned`: `timesheetSelfSigned(person, roster)`.
4. **Store what the person signed** — at the operative signature (`Views/InvoicingView.swift` ~2438, `draft.operativeSignedAt = Date()`), set `operativeSignedBookings = signedTimesheetBookingRecord(liveLines)` from the same live lines the screen shows, and write it with the signature (owner write; `timesheetOwnerWriteFields` keeps it). 6. **The sheet** — while `waitingFor == "person"` the person's sheet shows the same message and offers "Review and sign again" (the normal sign flow, writing a new signature and step 4's record); the old manager signature is not shown as signing it off. A sheet with `reopened` shows the **live** bookings' figures: give `timesheetTotals` / `timesheetInvoiceRows` the sheet **without** `weeklyReportOverride` (web `draftForFigures`); never show, invoice or export the stale snapshot. Generate Invoice is off while `signedTimesheetActions(change).mayGenerateInvoice` is false.
7. **Line manager's review** (`OperativeTimesheetReviewView` and the counter-sign path ~930–955): while `waitingFor == "person"` show `reviewerMessage` and **no** counter-sign; when `waitingFor == "lineManager"` show `reviewerMessage` and offer counter-sign **again** even though `managerSignedAt` is stored. That counter-signature (and a self-signed person's re-signature) **rebuilds the snapshot from the live bookings** (`rebuildSnapshot`: in `Core/TimesheetWeeklyReportOverrideBuilder.swift` build it fresh as at first approval, with the new signatures, instead of re-applying reviews to the stored lines). Never rebuild an exported sheet. An exported sheet with `changed` shows `reviewerMessage` (`SIGNED_TIMESHEET_EXPORTED_CHANGED_MESSAGE`) only.
8. **Lists, counts, export** — every Awaiting / Signed off / Exported decision passes the sheet's change to `timesheetListBucket(fields, hasLineManager, change)` (`InvoicingView.swift` ~920, the hub tile counts, User Timesheets lists): reopened + person → `unsigned`, reopened + line manager → `awaiting`, exported stays `exported`. `exportSignedTimesheets` (~4008) skips any sheet whose `signedTimesheetActions(change).mayExport` is false (re-check on the freshly read sheet before stamping `exportedAt`).
