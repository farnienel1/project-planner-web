## What changed in 1.21.0

- Job lists are one shared rule (new §21, `lib/canonical/worksLists.ts`): list membership `worksListMembership` (every document of the collection, inactive included; collection decides the kind), per-viewer visibility `visibleJobs` / `operativeJobIds` / `worksListPersonIds`, tabs and counts `jobWorkStatus` / `worksTab` / `worksInTab` / `worksTabCounts` (inactive → Completed; All = every row), booking pickers `bookableJobs`, Home `activeJobsCount`. Stores keep every job: web's shared `projectsIncludeInactive` flag (Projects, Clients and Site Audit hid inactive projects, and changed the store for every other screen by load order) and iOS `ProjectStore.smallWorks` (live only) are removed.
- Operatives see jobs through tasks as well as bookings and deadlines on web too (§17 already said so); web read their job documents from bookings only.
- Booking pickers offer only jobs that are visible, not inactive and writable (`bookableJobs`; web Book labour skipped `canWriteBooking`; My Schedule and the Daily Overview sheet offered inactive jobs under Completed / All). Owner decision: the job's start and end dates are never checked — a job past its end date or with no end date stays bookable.
- A job's status day is the organisation zone everywhere (`jobWorkStatus` takes the zone as a required argument; web defaulted to London).
- Web Daily Overview decides small works by collection (`jobKind`), not by `jobType` text.
- `parseJobDocument` reads a numeric `jobNumber` as text.
- iOS hand-off (audit findings 1–5, 10, 13, 14), every file below calls the §21 functions through `CanonicalBusinessEngine` and keeps no list rule of its own: `Core/ProjectStore.swift` (`smallWorks` keeps every document — drop the `isLive` filter at ~984-986; lookups use the full list); `Views/ProjectSmallWorksRevampTokens.swift` (`WorksListStatusCounts` → `worksTabCounts`, inactive under Completed, All = rows); `Views/ProjectsView.swift` and `Views/SmallWorksView.swift` (membership `worksListMembership`, visibility `visibleJobs` instead of their own code and the name fallback, chips `worksInTab`); `Views/TasksDetailView.swift`, `Views/WeeklyReportView.swift`, `Views/ScheduleOperativeView.swift` and the `TimesheetPayrollCollector` call sites (`Views/InvoicingView.swift`, `Core/WeeklyReportTimesheetFeed.swift`) look jobs up in the full list; `Navigation/MainMenuCatalog.swift` ("N open" → `worksTabCounts(...).active` over `visibleJobs`); `Core/WorkAccess.swift` (`visibleWorks` / `operativeVisibleProjectIds` → `visibleJobs` / `operativeJobIds`; home count at ~128-171 → `activeJobsCount`, used by `Views/HomeView.swift`); `Views/BookLabourFlowView.swift` and `Views/MyScheduleView.swift` (job pickers → `bookableJobs`; never filter on the job's dates); `Views/SiteAuditView.swift` (counts `worksTabCounts`); `Core/ProjectStatusRulebook.swift` / `Models/ProjectModels.swift` (status → `jobWorkStatus` with the organisation zone, no `Calendar.current` fallback). Delete dead `Models/ProjectWorksMerge.swift` `dedupeByJobNumber`.
